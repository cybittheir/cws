# Модель данных

## Базовые сущности

```text
UserAccount
 └── Person
      ├── CompanyMembership
      │    ├── EmploymentPeriod
      │    ├── MembershipDepartment
      │    └── CompanyRole
      └── UserPreference

Company
 ├── CompanyDomain
 ├── Department
 ├── Calendar
 ├── NotificationPolicy
 └── PhonebookProfile
```

## Сущности первой очереди

| Сущность | Назначение |
|---|---|
| `companies` | Компания, название, логотип, часовой пояс, тема по умолчанию |
| `company_domains` | Домены и поддомены компании |
| `users` | Учётная запись, пароль, статус, MFA, блокировка |
| `persons` | Общие персональные данные человека |
| `company_memberships` | Участие человека в компании, роль, рабочие контакты, статус |
| `employment_periods` | История приёма, последнего рабочего дня и увольнения |
| `departments` | Иерархия подразделений |
| `membership_departments` | Основное/дополнительные подразделения, руководство |
| `user_preferences` | Тема, язык, тихие часы, каналы уведомлений |
| `audit_logs` | Неизменяемый журнал значимых действий |

## Сотрудник в нескольких компаниях

Один `UserAccount` и одна `Person` могут иметь несколько `CompanyMembership`. У каждого membership могут быть свои должность, рабочий email, телефоны, роль, подразделения, кадровые даты и статус.

При повторном приёме сотрудника старый трудовой период сохраняется, а доступ к аккаунту разблокируется и создаётся/активируется новый `EmploymentPeriod`.

## Правила уникальности

- Рабочий email уникален в пределах компании.
- Табельный номер, если используется, уникален в пределах компании.
- У сотрудника может быть ровно одно основное подразделение и ноль или более дополнительных.
- У одного membership ровно одна роль в компании.
