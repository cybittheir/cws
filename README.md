# Corporate Workspace — этап 2

Рабочий вертикальный срез: **вход → компания → справочник → мой профиль → изменение собственных контактов → аудит**.

## Важно

Для компактного запуска в этой поставке используется `memory.Store`: демонстрационные пользователи и сотрудники хранятся в памяти и сбрасываются после остановки процесса. Интерфейсы репозитория и черновики миграций уже добавлены; реальный SQL-репозиторий будет подключён следующим техническим шагом перед импортом и production-эксплуатацией.

## Запуск

```bash
go mod tidy
go fmt ./...
go run ./cmd/server
```

Откройте http://localhost:8080

## Демо-учётные записи

| Email | Пароль | Компании |
|---|---|---|
| `admin@alpha.example` | `demo` | Альфа (администратор), Бета (руководитель) |
| `ivan@alpha.example` | `demo` | Только Альфа (сотрудник) |

Для Анны отображается переключатель компаний: она состоит в двух компаниях. Для Ивана вместо переключателя показывается название единственной компании.

## Реализовано

- cookie-сессия;
- демонстрационный логин;
- доступ к справочнику только после входа;
- роли в рамках company membership;
- разные роли в разных компаниях;
- структура подразделений и группировка строк;
- автоматическая логика колонки города: отображается только при двух и более городах;
- быстрые ссылки Telegram/Mattermost;
- редактирование собственных мобильного телефона, личного email и ссылок чатов;
- optimistic locking через поле `Version`;
- запись изменения контактов в audit repository;
- исправленный шаблон вложенного `range`: применяется `{{$department := .}}`, поэтому ошибка `$.Name` отсутствует.

## Ограничения этапа

- нет настоящей SQL-БД и мигратора;
- пароль `demo` проверяется только для демонстрации;
- выбор компании ещё не сохраняет изменение в реальном серверном хранилище сессии;
- добавление сотрудников и архив доступны лишь как план интерфейса;
- MFA, импорт, SIP XML, рассылки и календарь пока отсутствуют.
