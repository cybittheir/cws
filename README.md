# Corporate Workspace — этап 2.1

Эта поставка заменяет демонстрационное хранение в памяти на **реальную SQLite-базу**. Данные, профили, серверные сессии и аудит переживают перезапуск приложения.

## Быстрый запуск

```bash
go mod tidy
go fmt ./...
go run ./cmd/server
```

Откройте http://localhost:8080

При первом старте создаётся `data/corporate-workspace.db`, применяются встроенные миграции и записываются демонстрационные данные.

## Учётные записи

- `admin@alpha.example` / `demo` — две компании.
- `ivan@alpha.example` / `demo` — одна компания.

## Реализовано

- SQLite через CGo-free драйвер `modernc.org/sqlite`;
- SQL-схема встроена в бинарник через `go:embed`;
- автоматическое создание схемы и начальных демонстрационных данных;
- bcrypt-хеширование демо-пароля;
- непрозрачная случайная серверная сессия в таблице `sessions`;
- хранение активной компании в серверной сессии;
- выход отзывает сессию;
- реальные чтение справочника и обновление своих контактов;
- optimistic locking и аудит изменения контактов;
- исправленный шаблон вложенного `range` (`{{$department := .}}`).

## Ограничения

На этом этапе поддерживается только SQLite. Конфигурация PostgreSQL/MySQL сохраняется как будущая точка расширения. MFA, CRUD сотрудников, импорт, SIP-каталог, рассылки и календарь ещё не реализованы.

## Проверка

```bash
go vet ./...
go test ./...
go build ./cmd/server
```

Чтобы начать заново с демонстрационными данными, остановите сервер и удалите файл `data/corporate-workspace.db`.
